## 使用流程

1. 输入**接手时**现场剩余抽数，确认每款各一份、盒内均匀不放回抽取的测试假设。
2. 选价格或喜好，填写14款固定估值、单抽价格和可选硬预算。喜好权重100/60/20/0/−30及愿付尺度100只是可编辑示例，未做科学校准。价格空白代表未知，不会当作0。
3. 明确用户目标：喜好可选仅我推／我推加不错；价格模式逐款勾选目标。目标定义**命中风险统计**，推荐目标函数仍是全部固定估值减去新增花费，不自动变成命中即停或只追目标。
4. 选择残盒生成假设。随机移除是对照；策略模式需要明确前人的目标、命中几款停手和最多抽数。前人目标独立选择，不默认为与你相同。抽数上限只有在前人价格和预算已知时才能换算为预算限制。
5. 查看下一抽命中、盒内零目标、同一可执行策略最终未命中概率、预计追加支出和结果分布。另列强制抽空剩余N件的命中率与成本，该对照假设预算足够。
6. 抽取后录入实际角色和立绘，更新后验与建议。查看建议本身不改预算或库存。确认结果计一次，支持事件ID幂等、撤销、保存恢复及JSON导入导出。

估值在会话内固定。修改需明确建立新会话，旧账本保留旧解释。v2使用独立浏览器存储键，不改删v1会话；v1导入明确拒绝，不静默升级先验。此前v0.1程序和ZIP保留，可继续读取旧记录。

## 残盒模型

每款一份仍是**未核实装箱假设**。前人在满14件开始，仅根据自己已抽到的结果逐步抽取或停手，得到结束时剩余集合的精确联合分布，再按接手时观察到的N条件化。

支持的机制是独立情景，不赋予未经数据支持的现实混合比例：

- `random_removal`：N外生给定，均匀N子集，仅为随机移除对照；不捏造N在现实中的出现频率。
- `fixed_draws`：前人固定抽指定次数后离开，N必须与之相容。
- `target_stop`：前人抽到指定数量的目标后停，或达到明确的最多抽数。前人目标可与用户不同。

对不能产生给定N的规则返回`UNSUPPORTED_N`；对后验概率为0的观察返回`UNSUPPORTED_OBSERVATION`。错误不会编造先验或把不可能结果记入账本。各机制同时报告其未入场、抽空和非空残盒频率；这些是情景模型的频率，不是实测人群比例。

设前人停手后N件集合的权重为w(S)，自己已观察集合为O。固定N且盒内均匀抽取时，所观察顺序的似然因子对所有含O的S相同，因此更新为保留S包含O的权重并归一化。令Z(O)=sum[w(S):S包含O]，下一抽款i的概率为：

```text
p(i | O,N) = Z(O ∪ {i}) / ((N − |O|) × Z(O))
V(O,h) = max(0, sum_i p(i | O,N) × [value_i − cost + V(O ∪ {i},h−1)])
h = min(实际剩余抽数, 硬预算可负担抽数)
```

用14位bitmask和超集质量变换精确求解。动作只使用可见的O、信念和预算；不会先对每个真实隐藏库存取最优再平均。支持随机基线和所选行为机制的独立比较，没有隐藏库存偷看或未来信息泄漏。

数值实现采用1e-9近零平局容差，平局动作停手、继续价值置0；这只是数值约定，不是安全概率阈值。

未来风险沿**上述同一个信念最优策略**传播终止状态，计算新增抽数、目标数、支出、净效用为负的概率和结果分位数。分位数是结果分布分位数，不是置信区间。

“未来累计净效用（含下一抽）”包含当前至未来停手的全部新增效用与成本，不重复扣沉没支出，不是停手权额外增加的收益。若想核算完整会话，还需计入已抽款效用和此前花费。个人喜好元等值不可当成现金利润。

未知前人行为不能由N单独识别。界面显示所选情景与随机对照的差异；动作有分歧时提示假设敏感，证据不足时不把正均值包装成可靠的购买保证。没有人为设置“安全概率”阈值。

## 可复现合成案例

以下均是测试数据，不是用户当前赋值或真实校准。

**截图算例：**接手时剩5，之前9件未知移除，自己记录维伊常规、哈蒂娅精英二后，实际剩3、未亲自观察身份12。剩余档位计数2/4/0/4/2，权重100/60/20/0/−30、愿付尺度200、单价25、预算不限。

| 随机移除基线指标 | 精确结果 |
|---|---:|
| 下一抽估值／净值 | 190/3 ／ 115/3 |
| 未来累计净效用／预计追加支出 | 115 ／ 75 |
| 目标仅我推2款：下一抽／零目标／强制抽空至少中1款 | 1/6 ／ 6/11 ／ 5/11 |
| 目标我推加不错6款：下一抽／零目标／强制抽空至少中1款 | 1/2 ／ 1/11 ／ 10/11 |

本例每个可达分支均继续，累计115等于未来总估值190减成本75。愿付尺度100时，同档位的下一抽估值31.6667、净6.6667、未来最优净效用20.4697；不能只看档位反推尺度。

**同N不同机制：**前人目标显式设为A、B两款，最多14抽，接手N=4。

| 前人规则 | 留下N=4的概率 | 当前盒中目标数 | 下一抽目标概率 | 盒中零目标概率 |
|---|---:|---|---:|---:|
| 中第一款目标即停 | 4/91 | 恰好1 | 1/4 | 0 |
| 两款目标均中才停 | 9/91 | 0 | 0 | 1 |
| 随机移除对照 | N外生给定 | 0/1/2都有可能 | 1/7 | 495/1001 |

这证明策略偏差可以提高或降低命中率，不能强制新模型结果更低。

## API和分层

`schema_version=2`、`model_version=residual-items-v2`；catalog另行版本化。纯函数`dispatch(request,catalog)`支持create/recommend/record/undo/restore，输入输出可JSON序列化，无文件系统或网络依赖。状态包含完整固定配置及事件账本。

Python与JS使用同一数学模型和契约，完整JSON对照测试覆盖成功及错误。运行配置、API或核心版本不符会报错，不静默降级成随机模型。

| 文件 | 作用 |
|---|---|
| engine.py / public/model.mjs | Python基准与JS独立实现 |
| server.py / public/api.mjs | 本机HTTP服务及计算提供方 |
| public/app.mjs / index.html / styles.css | 前端交互与布局 |
| public/ui-utils.mjs | 概率与风险展示纯函数 |
| public/data/box54.json | 盒型、款式、目录版本与来源 |
| reference_cli.py | stdin/stdout JSON跨语言测试基准 |

五档模式检查固定values与权重、尺度、档位的一致性，不一致报`VALUATION_MISMATCH`。独立API合成案例可显式用`valuation_meta.kind=explicit_values`，界面不凭空补齐五档含义。未知参考价格仍是null。
